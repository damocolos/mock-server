Dynamic Mock API Engine

Build and test robust client applications with instantaneous mock responses. Create custom status codes and payloads on demand, then trigger them via wildcard paths and any HTTP verb.

1

Register API Mock

Send a POST /api/mocks request specifying your desired HTTP status_code and response JSON payload. Receive a generated UUID.

2

Invoke Wildcard Path

Call /api/dynamic/:id/*path using any HTTP method (GET, POST, PUT, DELETE, etc.). The server returns your exact configured mock response.

3

Update On The Fly

Use PATCH /api/mocks/:id anytime to alter the returned status code or payload without needing to recreate the endpoint or reconfigure client URLs.

POST /api/mocks

Creates a new dynamic mock endpoint configuration in the database. Returns a unique UUID id that you can invoke via /api/dynamic/:id/*path.

Request Body (JSON)
Field Type Requirement Description
status_code Integer Required HTTP status code to return when triggered (e.g. 200, 201, 400, 404, 500).
response JSON / Object Required The payload returned in the mock response body. Can be an object, array, or JSON primitive.
label String Optional Human-readable label or description for this mock (e.g. "Order Created 201").
Code Examples
curl -X POST "{ORIGIN}/api/mocks" \
  -H "Content-Type: application/json" \
  -d '{
    "status_code": 200,
    "label": "User Profile Success",
    "response": {
      "id": 101,
      "name": "Jane Doe",
      "status": "active"
    }
  }'

            ALL
            /api/dynamic/:id/*path
          

          
        


        

          The Mock Simulator Gateway: Accepts ANY HTTP verb (GET, POST, PUT, DELETE, PATCH, OPTIONS) and any nested subpath. Looks up the mock configuration by UUID and immediately returns the stored status code and response payload.
        


        
Path Parameters

        

          

            
              

                Parameter
                Type
                Requirement
                Description
              

            
            
              

                id
                UUID
                Required
                The unique ID of the mock definition to trigger.
              

              

                *path
                Wildcard String
                Optional
                Any subpath or route (e.g. /v1/users/42, /payments/charge). Can also be left empty.
